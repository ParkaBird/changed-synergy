# 兽化玩家的友好搂抱设计

> 历史实现记录（2026-10-26）。下文 Alpha.2 环境和验收结论仅对应当时版本；现行操作见[社交指南](SOCIAL_GUIDE.zh-CN.md)。

日期：2026-10-26。本文记录友好搂抱的实现范围和约束。

## 已确定的范围

沿用主模组的擒抱能力及能力栏位置，通过右键该能力选项切换“战斗擒抱／友好搂抱”。
不另外增加一项几乎相同的能力，也不改变其他能力的操作。

先检查当前形态真正拥有的能力实例。有擒抱能力，才适配其作为发起者的动作；
没有擒抱能力，不补发能力、不设计抱人动作，但仍可以作为被抱的一方。
这一规则同样适用于幼崽、牛奶布丁、野生鲨鱼、无头骑士和 Addon 的四足雪豹形态。

陌生和敌对胶兽也可以尝试搂抱。它们保留反抗及原有敌意，搂抱不会自动建立关系、
洗掉仇恨、改变声望或给予兽化停战。已建立关系的胶兽可以有配合姿态，不能因此取消玩家的挣脱权。

## 操作

| 场景 | 行为 |
| --- | --- |
| 能力轮盘上右键擒抱选项 | 在战斗擒抱与友好搂抱之间切换；显示当前模式，消费这次右键，避免同时触发别的二级功能。 |
| 左键选择能力、使用能力键 | 保留现有选择与发动方式；长按轮盘的松键确认仍只选择能力。 |
| 友好模式下抱住目标后按左键或右键 | 不造成伤害、兽化、吸收或包裹，不把控制权交给被抱者；首版不额外绑定其他动作。 |
| 发起者使用原生释放操作 | 主动放下目标。 |
| 被抱玩家操作原生挣脱 QTE | 正常减少擒抱强度并挣脱；人类与已兽化玩家均适用。 |
| 正在抱住目标时尝试切换模式 | 拒绝并提示先释放，防止一次友好搂抱在途中变成攻击或吸收。 |

模式偏好按玩家保存，适配普通兽化及当前支持的 TT 控制身体；每次实际搂抱冻结本次模式。
活动中的搂抱不作为永久状态存档。登录恢复、死亡和变形不能留下无主的抓取关系。

能力名称和提示明确显示“擒抱 · 战斗”或“擒抱 · 友好”，使用原来的图标并附一个小型友好标识。
不通过颜色单独传达模式。补齐中英俄文本。

## 目标及无伤约束

保留原先可擒抱的人类与人形怪物；友好模式再允许具备安全抱姿的胶兽 NPC 和兽化玩家。
继续遵守主模组玩家擒抱开关，不绕过 Boss、特殊生命周期实体和服务端禁用条件。

服务器校验距离、视线、双方存活、当前身体、目标是否已被抓取，以及是否正在骑乘、包裹、接管或参与其他占用身体的互动。
友好搂抱不能偷走别人的目标，不能把羁绊包裹强制拆开，也不能形成相互抱住或多人套娃。

友好状态同时阻断伤害计算、兽化决策和进入 `suited` 状态；不能只隐藏提示或依靠客户端清空按键。
兽化玩家不会因为被抱就被当成无效目标释放，也不会被移除原来的种族、性别、外观或关系数据。

被抱玩家始终保留原生挣脱，NPC 定时友好擒抱也必须提供 QTE。无 AI 更新的抓取由独立的玩家挣脱更新兜底，同一游戏刻不重复推进；漏收初始随机种子时由服务器同步恢复。
友好搂抱的释放与挣脱不额外施加攻击伤害、逃脱反伤或敌对擒抱的僵直。主动释放和 NPC／玩家挣脱均结束当前按住操作，并给予双方两秒友好擒抱冷却；松开后重新按键才可再次开始。
这不会额外赋予兽化停战或清除别处发生的战斗。

被抱 NPC 暂停攻击、寻路、工作和物品拾取。拒绝或挣脱的反应沿用它自身的抵抗规则，不能仅因“友好”二字而使敌对者永久配合。
释放后按当下的关系和战斗规则恢复行为，保留有效的敌意记忆，不强塞一个已经失效的旧攻击目标。
不反复发放好感奖励。
外来战斗和救援优先，发生时先安全结束友好搂抱，再走原来的处理流程。

## 抱姿

### 普通人形

以主模组双臂环抱为基础，按被抱体型校准前后间距、承托高度及手臂角度。
目标不陷进发起者身体，不被夹住脖子；第一人称相机不能落在另一方胸腔内。
成年和较大体型通常使用站立环抱，不能一律抬到幼崽的高度。

### 幼崽与小型四足

幼崽混合使用两种姿势：仰面横抱时头部略高于髋部，一只手托头颈、另一只手托住身体；直立抱时在前爪／腋下附近承托上半身，让腹部和后腿自然下垂。服务端每次抱起时选择一次，同步给客户端，持续搂抱时不切换。直立抱的目标背对发起者，双方大致朝同一方向。

- 发起者抬高双臂，承托前爪根部附近；不通过把幼崽前爪压到腹部来凑接触位置。
- 被抱者躯干由原姿态平滑转为略向前倾的直立姿态，头部留出自然活动范围。
- 前爪朝前下方，肘部轻弯；后腿从髋部自然下垂，膝踝放松，不绷成站立姿势。
- 直立抱时前爪贴近身体两侧，尾巴自然向下垂；横抱时头颈、尾根和各段尾巴保持与身体连接。
- 胸腹位于发起者胸前偏下，按双方尺寸调节高度，不缩放目标来强行塞进同一个模板。
- 行走时仅加入很轻的随步摆动，停止跑步循环，避免悬空的四肢继续蹬地。

幼崽先使用项目现有的幼崽分类，再按实际模型骨骼适配，不能只用实体高度判断。
Addon 的 `latex_snep` 使用实际的四足骨骼适配；玩家的形态通过当前兽化实例解析，
包括 `changed_addon:form_latex_snep_feral`，不把主模组及 Addon 的其他直立雪豹套入四足抱姿。
大型四足、半人马和水生长身体不使用此模板。

### 指定特殊种族

具体的“抱人方”范围以本次能力核查表为准；无能力的形态只处理被抱姿势。

| 被抱对象 | 被抱姿势与定位 |
| --- | --- |
| 牛奶布丁 | 双手托住底部，布丁放在胸前偏下；保留软体的小幅晃动，不凭空生成四肢，不把它埋进躯干。 |
| 野生鲨鱼 | 侧面朝外竖抱，鱼头朝上、腹部位于双臂之间，双手分别承托和稳住身体，尾鳍轻微弯曲以避开地面。 |
| 无头骑士 | 该模型实际只有四足下半身；借用幼崽的直立抱法，抬高双臂承托前肢，较长后半身和后腿自然垂下，不虚构上半身或头部。 |

按用户确认，野生鲨鱼只适配被抱姿势。即使注册表中存在通用抓取实例，也禁用其发起入口和轮盘选项，不设计鱼鳍抱人动作。

野生鲨鱼、牛奶布丁、无头骑士、三种主模组狼幼崽和四足雪豹均不增加抱人姿势或能力。

## 位置、过渡和退出

复用主模组抓取关系、共同物理根位置、网络同步和挣脱流程。被抱身体通过原生 held-entity 层绘制一次，第一人称沿用原生抓取相机，不另外制造一个可互动的假身体。

新的胸前托抱不叠加已有的小体型通用抬高修正。每帧从原始骨骼姿态计算，防止持续抱住后偏移累积。
抱人者移除原生战斗擒抱的肩根前移／下移，让双臂仍连接躯干。仅在被抱者遮住脸的高位抱姿中，头部在颈部轻微歪向一边，不左右平移，不覆盖原有的转头朝向。牛奶布丁、无头骑士和幼崽低位抱法不触发；普通人形按双方身高及承托高度判断。
骨骼采用约 8 tick 入姿，释放时立即清除抓取和动作状态，恢复原生动画。
实体动作使用短时平滑过渡，后续按实际截图校准，不让身体像轮盘 UI 那样回弹。

主动释放和挣脱均调用统一落点修正：优先选择近旁能容纳完整体型的落点，水生目标保留合适的水中位置。
死亡、断线、卸载、切换形态或能力被撤销时立即解除关系，清理姿态、输入和物理标记，不加载远处区块，也不把玩家长期锁住。

## 兼容与实现落点

当前 Addon 已提供安全擒抱及右键扩展。安装时归并为同一个模式开关，不能让同一次右键被两套处理各翻转一次；
未安装时由 Synergy 在原生能力上提供相同行为，不增加 Addon 硬依赖。

现有全局排除项不能直接删除。牛奶布丁、野生鲨鱼、无头骑士和部分幼崽目前受 NPC 通用擒抱排除保护，
本次只给经过姿态适配的玩家友好搂抱开放相应目标，不连带开启 NPC 的敌对吸收、自动包裹或救援擒抱。

涉及的现有入口：

- `GrabEntityAbilityInstance`：选取目标、永久兽化玩家有效性、无伤处理、包裹入口、挣脱与释放。
- `AbilityRadialScreen` 及 Addon 二级操作：右键模式切换和提示。
- `GrabQteSyncMixin`：复用 QTE，同 NPC 脚本友好搂抱的自动结束分开处理。
- `HeldCreaturePositionMixin`、原生 `LatexHeldEntityLayer` 和各模型动画器：目标位置、托抱骨骼与单次渲染。
- `ReleasePlacementService`：统一解除后的落点修正。

已添加默认开启的服务端 `PlayerFriendlyHugs` 开关，以及默认开启、仍受主模组玩家擒抱开关限制的
`PlayerFriendlyHugPlayers` 子开关。关闭时安全结束现有友好搂抱，不能把它改成战斗擒抱。

## 验收

1. 右键只切换一次；普通轮盘、长按轮盘及安装／未安装 Addon 时提示一致。
2. 只有当前形态确实拥有擒抱能力才出现发起动作；所有指定对象可以按适配被抱。
3. 左键、右键、旧原生数据包及 Addon 二级操作均不能给友好目标造成伤害或推进兽化、吸收、包裹。
4. 人类玩家、兽化玩家和当前支持的 TT 玩家身体都能被抱和自行挣脱；原生 QTE 的错误、成功和防重放校验保留。
5. 陌生、敌对、熟悉及羁绊 NPC 各自保留关系与抵抗逻辑；释放不洗仇恨，不重复给好感。
6. 幼崽及四足雪豹逐种检查手臂接触、前后爪、尾巴和第一人称相机，转身及行走不漂移或出现双影。
7. 牛奶布丁、野生鲨鱼、无头骑士按能力核查结果分别检查被抱及有资格的发起动作。
8. 检查主动释放、被抱玩家挣脱、断线、死亡、形态变化和区块卸载，确保无残留姿态、物理锁或无主关系。

## 能力核查

本轮在独立服务器中实际创建玩家形态，读取原生 `GRAB_ENTITY_ABILITY` 能力实例，
同时检查没有玩家形态的指定 NPC。没有向玩家或 NPC 补发能力。

环境：Changed 0.15.7、当前本地 Synergy 1.1.5-Alpha.2、TrueTransfur 2.0.1、Addon Plus 2.9.2c。

| 形态或实体 | 当前玩家擒抱能力 | 设计范围 |
| --- | --- | --- |
| `changed:form_latex_shark_feral` | 禁止发起 | 仅被抱时的竖向托抱；隐藏通用抓取入口。 |
| `changed:form_dark_latex_wolf_pup` | 无 | 仅作为被抱方，胸前托抱。 |
| `changed:form_pure_white_latex_wolf_pup` | 无 | 仅作为被抱方，胸前托抱。 |
| `changed:form_gas_wolf_pup` | 无 | 仅作为被抱方，胸前托抱；保留其气态外观。 |
| `changed_addon:form_latex_snep_feral` | 无 | 仅作为被抱方，适配四足骨骼的胸前托抱。 |
| `changed:milk_pudding` | 无原生玩家形态，NPC 也未持有擒抱能力 | 仅作为被抱方，底部承托。 |
| `changed:headless_knight` | 无原生玩家形态，NPC 也未持有擒抱能力 | 仅作为被抱方，前肢承托、后半身下垂的直立抱法。 |

对无头骑士的检查针对真正的 `headless_knight`，不把它替换成白胶半人马来推断能力。
后续若其他模组动态增减能力，仍以正在使用的当前形态实例为准，不把此表作为强制授予能力的名单。

另在未安装 Addon Plus 的独立服务器核查了六个主模组形态／实体，结果相同。
核查均使用独立测试存档，不触碰玩家的实际世界。

## 实装验证

安装和不安装 Addon Plus 的独立服务器、客户端均通过检查。覆盖原生能力限制、右键模式切换、无伤／无兽化／无包裹、手动释放、玩家原生 QTE、TT 2.0.1 独立身体、同次搂抱姿势稳定性、重复 tick、配置关闭及形态保留。纯白幼崽增加了前爪与全部头部／口鼻模型方块不相交的几何检查，抱人者双臂检查了与当前躯干肩根的连接，并逐种检查双角度实机截图。

生产包通过发布校验，未包含测试类；全部随包字节码和资源与实测包一致。本次同时应用 Crossader 的新版结构，详见 `RESEARCH_STRUCTURES.md`。本地 Alpha.2 和测试专用配置使用同一份 JAR，未发布。尚未进行真实多人联机测试。
