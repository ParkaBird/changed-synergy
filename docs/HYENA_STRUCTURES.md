# Hyena's Hideout and camps

Buildings by **Crossader**. Each small camp generates with two persistent male Latex Spotted Hyenas. The hideout generates with four males and exactly one female. Native structure-local spawn tables replenish males only, while wild tropical biome spawning retains both sexes. Outside these structures, ordinary biome spawning is limited to jungle and savanna families; plains, desert, badlands and snowy biomes do not receive global hyena spawn entries. The existing authored inhabitants, supplies and story items remain unchanged.

| Structure ID | Source | Natural biomes |
| --- | --- | --- |
| `changed_synergy:hyena_hideout` | `hyena_hideout.nbt` | Savanna family |
| `changed_synergy:hyena_camp_tropical` | `hyena_camp1.nbt` | Jungle and savanna families |
| `changed_synergy:hyena_camp_open` | `hyena_camp2.nbt` | Desert, badlands family, plains and sunflower plains |
| `changed_synergy:hyena_camp_snowy` | `hyena_camp3.nbt` | Snowy plains |

The hideout has a separate 32-chunk spacing / 5-chunk separation placement set with triangular spread, matching ocean-monument placement parameters. Camps share a 24 / 8 set, selecting the biome-appropriate template, and avoid hideout candidate chunks within four chunks. Hideouts avoid Changed's decayed-lab placement set within six chunks. Biome and terrain restrictions still determine actual frequency. Tropical camp storage can also contain a hideout explorer map; see `NATURAL_CAMPS.md`. All require ordinary structure generation in newly generated Overworld terrain. `/locate structure changed_synergy:<ID>` and `/place structure changed_synergy:<ID>` use the vanilla registry.

The hideout's authored surface is local Y=3; its three basement layers are embedded in the terrain. Camps use local Y=0. The existing template structure type gains optional `ground_level` and `max_terrain_slope` fields; old laboratories retain their original defaults and placement. These four structures use no beard terrain adaptation: the template already includes its surface soil and the hideout basement, so adapting the neighboring terrain to its lowest block would expose a one-block step or the basement as a raised platform. Camps reject terrain differences above two blocks and the hideout above three, retaining the existing water rejection and short foundation supports. Buried supports below gravel or sand use stable dirt, so gaps beneath the foundation cannot start a cascade of falling blocks; the authored gravel remains in place.

The original Downloads files are untouched. `tools/adapt_hyena_structures.py <input-folder>` imports the runtime resources with `nbtlib` and records hashes in `tools/hyena_structures_manifest.json`. It strips empty Visual Workbench data from the three original vanilla crafting tables, empty Changed cover records, old entity UUIDs and optional capability/attribute snapshots. It also restores the missing export-corner ground column beside the hideout's well chest at local X=0, Z=0: stone at Y=0, dirt at Y=1–2 and grass at Y=3, matching the neighboring ground. No extra mod is required beyond Changed and Synergy. Loot tables, supplies, banners, paintings, sheep and other authored contents are retained; the draft-book chest beside the well is removed. New hyena residents are appended on safe authored floor blocks, without replacing existing occupants or block contents. Existing generated buildings are not rewritten or repopulated.

`tools/tests/hyena-structures.init.gradle` checks registries, block states, loot, biome selection, terrain anchoring and saved rotations on a real dedicated server. The existing stability fixture accepts `-Dchanged_synergy.stabilityHyenas=true` and `-Dchanged_synergy.stabilityAllRotations=true` to check the four layouts in all rotations while actual world ticks run.
